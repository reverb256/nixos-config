## 6. Root Cause Analysis

### Problem: ResourceQuota Blocking Hardware Discovery

**ResourceQuota**: `akash-services-quota` in `akash-services` namespace

**Requirement**: All pods must specify `requests.cpu` and `requests.memory`

**Issue**: Hardware discovery pods (operator-inventory-hardware-discovery-*) use `psutil` container **without resource requests**

**Error**:
```
failed quota: akash-services-quota: must specify requests.cpu for: psutil;
requests.memory for: psutil
```

**Why It Matters**:
- Hardware discovery pods detect GPUs on each node
- Without discovery, operator-inventory has no node data
- Without node data, provider inventory shows 0 GPUs
- With 0 GPUs, provider cannot bid on leases

---

## 7. Recommended Fixes

### Option 1: Add Resource Requests to Hardware Discovery (Recommended)

**Steps**:
1. Find operator-inventory deployment/configuration
2. Add resource requests to `psutil` container:
   ```yaml
   resources:
     requests:
       cpu: 100m
       memory: 128Mi
     limits:
       cpu: 500m
       memory: 512Mi
   ```
3. Restart operator-inventory deployment
4. Verify hardware discovery pods start successfully

**Pros**:
- ✅ Fixes root cause
- ✅ Allows quota enforcement
- ✅ Minimal resource usage

**Cons**:
- Requires finding operator-inventory configuration
- May need to update deployment manifest

### Option 2: Exempt Hardware Discovery from ResourceQuota

**Steps**:
1. Create ResourceQuota with scope selector
2. Exempt pods with label `app: operator-inventory-hardware-discovery`

**Pros**:
- Quick fix
- Doesn't modify deployment

**Cons**:
- Weaker quota enforcement
- Less clean solution

### Option 3: Increase/Remove ResourceQuota (NOT Recommended)

**Steps**:
1. Delete or modify akash-services-quota
2. Allow pods without resource requests

**Pros**:
- Immediate fix

**Cons**:
- ❌ Removes quota protection
- ❌ Allows resource abuse
- ❌ Not production-ready
