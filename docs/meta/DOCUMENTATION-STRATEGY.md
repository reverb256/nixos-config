# Documentation Strategy

> **Status:** Canonical documentation reference
> **Last Verified:** 2026-08-09
> **Owner:** Documentation maintenance

## Authority model

1. **Checked-in architecture:** `docs/current-state.md` describes repository structure,
   authority boundaries, and verification commands. It is not a live health report.
2. **Generated runtime snapshot:** root `STATUS.md` is generated by
   `scripts/update-status.sh` from `cluster-state.nix` plus optional live Kubernetes
   queries. Its timestamps and source metadata must be checked before use.
3. **Operational policy:** `AGENTS.md`, `CONTRIBUTING.md`, and `DOCS-MAINTENANCE.md` are
   the canonical safety, contribution, and documentation policies.
4. **Active procedures:** verified runbooks under `docs/runbooks/`, `docs/ci-cd/`, and
   explicitly marked subsystem directories.
5. **History:** dated audits, incidents, completed plans, and research under
   `docs/archive/` or explicitly marked historical files.

`docs/LIVE/` is retained only as a compatibility-pointer directory. It is not a current
source of truth and must not receive new operational documents.

## Directory structure

```text
docs/
├── current-state.md                 # Checked-in architecture boundary
├── runbooks/                         # Active recovery and operations procedures
├── ci-cd/                            # Active build/deploy workflow reference
├── operations/                       # Active subsystem operations references
├── plans/                            # Active plans; require verification metadata
├── kubernetes/                       # K8s architecture and operations references
├── archive/                          # Historical and superseded material
│   ├── obsolete/
│   └── legacy/
├── LIVE/                             # Compatibility pointers only
└── meta/                             # Policy and verification tooling
```

The separate `kubernetes-manifests/` tree contains manifests and agent guidance; its
README/AGENTS files must identify whether a document is live, bootstrap-only, generated,
test, vendor, or archived. The checked-in Nix/Easykubenix modules are authoritative where
they generate the deployed object; raw manifests remain separate sources where explicitly
used.

## Metadata classes

- **Canonical/Active/Reference:** `Status`, `Last Verified`, and `Owner` or `Source`.
- **Generated:** `Status`, `Generated By`, and `Source of Truth`.
- **Historical/Archived:** original date plus a visible non-authoritative warning.
- **Pointer:** retirement date and link to the replacement/preserved source.

Verification dates are evidence, not decoration. Never update one without checking the
content against source/configuration and live state when the document makes runtime claims.

## Verification

Run from the repository root:

```bash
just docs-audit
./docs/meta/VERIFICATION-SUITE/run.sh
```

The suite checks the explicit active-document set declared in
`docs/meta/VERIFICATION-SUITE/ACTIVE-DOCUMENTS.txt`, repository-relative links, required
source-of-truth paths, and retired-LIVE authority claims. It intentionally excludes
historical/archive content from freshness checks while preserving it for review.

CI must fail when this suite fails. A warning-only documentation check is not evidence
that the repository is healthy.

## Migration rule

When replacing a document:

1. classify it;
2. identify inbound references;
3. preserve historical evidence;
4. move or tombstone with an explicit replacement link;
5. update indexes and tooling in the same change;
6. run the complete documentation suite and review the diff.
