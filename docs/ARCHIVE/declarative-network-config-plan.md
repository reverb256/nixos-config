# Declarative Network Configuration Plan

**Status:** Draft | **Owner:** j_kro | **Created:** 2026-04-23

## Problem Statement

Network configuration is currently scattered and inconsistent:
- DNS configuration varies across hosts (zephyr had `1.1.1.1` first instead of `127.0.0.1`)
- `.lan` name resolution not working consistently
- Unbound configuration duplicated in multiple places
- No single source of truth for network parameters
- DHCP can override manually configured DNS settings

## Architecture Principles

1. **Single Source of Truth:** `/etc/nixos/` on zephyr (NFS-shared)
2. **Declarative Only:** No imperative DNS/resolv.conf modifications
3. **DRY:** Network parameters defined once, reused everywhere
4. **Host-Agnostic:** Configuration works on any host in cluster
5. **Reproducible:** Same config → same network state every rebuild

## Phase 1: Create Centralized Network Modules

### 1.1 Cluster DNS Module (`modules/network/cluster-dns.nix`)

**Purpose:** Single module that configures DNS identically on all hosts

**Key Features:**
- Force DNS order: `127.0.0.1` (unbound) first, never allow DHCP override
- Configure unbound with cluster-wide `.lan` records
- Set up DNS search domains: `lan cluster.local taila21e09.ts.net`
- Disable systemd-resolved (conflicts with unbound)

**Implementation:**
```nix
{ config, lib, pkgs, ... }:
let
  inherit (lib) mkIf mkOption types;
  cfg = config.networking.cluster.dns;
in {
  options.networking.cluster.dns = {
    enable = mkEnableOption "Cluster DNS configuration";
    upstreamServers = mkOption {
      type = types.listOf types.str;
      default = [ "1.1.1.1@853" "1.0.0.1@853" ];
      description = "Upstream DNS servers for non-cluster queries";
    };
  };

  config = mkIf cfg.enable {
    # Disable systemd-resolved
    services.resolved.enable = false;

    # Unbound configuration
    services.unbound = {
      enable = true;
      settings = {
        server = {
          interface = [ "127.0.0.1" config.networking.cluster.hosts.${config.networking.cluster.hostName}.ip ];
          access-control = [ "127.0.0.0/8 allow" "10.1.1.0/24 allow" "10.244.0.0/16 allow" ];
          # Force DNS order - don't accept DHCP overrides
          do-not-query-localhost = true;
          hide-identity = true;
          hide-version = true;
        };
        forward-zone = [
          { name = "ts.net."; forward-addr = [ "100.100.100.100" ]; }
          { name = "."; forward-addr = cfg.upstreamServers; forward-tls-upstream = true; }
        ];
      };
    };

    # NetworkManager DNS configuration
    networking.networkmanager.dns = "none";  # Use unbound, not NM
    networking.networkmanager.appendNameservers = [ "127.0.0.1" ];

    # Static resolv.conf (prevent DHCP overrides)
    environment.etc."resolv.conf".text = ''
      # Generated by NixOS cluster-dns module
      ${lib.concatStringsSep "\n" (map (s: "search ${s}") cfg.searchDomains)}
      nameserver 127.0.0.1
      nameserver ::1
      options edns0 trust-ad
    '';

    # Firewall for DNS
    networking.firewall = {
      allowedUDPPorts = lib.mkOptionDefault [ 53 ];
      allowedTCPPorts = lib.mkOptionDefault [ 53 ];
    };
  };
}
```

## Phase 3: Update Host Configurations

### 3.1 All Hosts (`hosts/*/configuration.nix`)

**Change from:**
```nix
clusterNetworking = {
  enable = true;
  hostName = "zephyr";
  # ... scattered DNS config
};
```

**To:**
```nix
{
  imports = [ ../../modules/network/cluster-dns.nix ];

  clusterNetworking = {
    enable = true;
    hostName = "zephyr";

    enable = true;
    # Inherit defaults from network-constants.nix
  };
}
```

## Success Criteria

- ✅ All hosts have identical DNS configuration structure
- ✅ `.lan` names resolve correctly on all hosts
- ✅ `resolv.conf` survives `nixos-rebuild switch`
- ✅ No imperative DNS modifications needed
- ✅ Gateway and all services use declarative hostnames
- ✅ Single source of truth: `/etc/nixos/` on zephyr

## Risk Mitigation

**Risk:** Breaking existing DNS during migration
**Mitigation:** Test on single host first (forge → sentry → nexus → zephyr)

**Risk:** K8s service DNS not accessible from host
**Mitigation:** Use ClusterIP addresses for host services, K8s DNS only for cluster-internal

**Risk:** DHCP overrides DNS settings
**Mitigation:** Static `environment.etc."resolv.conf"` prevents DHCP modifications
