# Static DNS Mapping

**Created:** 2026-05-19
**Last Verified:** 2026-05-19
**SSOT:** `modules/network/cluster-dns.nix`

## Architecture

All DNS resolution is static — no avahi/mDNS, no DHCP-based updates.

```
Application → /etc/resolv.conf (127.0.0.1) → Unbound → local-data records
                                                    → forward-zone: cluster.local → CoreDNS (10.0.0.10)
                                                    → forward-zone: . → 1.1.1.1@853, etc.
```

## Resolution Chain

1. **`/etc/resolv.conf`** — Static, managed by `cluster-dns.nix`. Nameserver: `127.0.0.1`
2. **Unbound** — Local DNS resolver, serves `.lan` domains via `local-data` records
3. **`/etc/hosts`** — Static entries from `networking.nix` + `cluster-dns.nix`
4. **CoreDNS** — K8s internal DNS (`cluster.local`), forwarded by Unbound

## Adding a New .lan Service

1. Add domain to the appropriate list in `modules/network/cluster-dns.nix`:
   - `hostServiceDomains` — via VIP (Caddy ingress)
   - `forgeServiceDomains` — via Forge
   - `sentryServiceDomains` — via Sentry
   - `hermesServiceDomains` — via Nexus
2. Add Caddy route in `hosts/zephyr/caddy-routes.nix` or `modules/services/cluster-services.nix`
3. Deploy K8s Service with matching `nodePort` (if applicable)
4. Run `just deploy` — DNS, TLS SANs, and /etc/hosts update automatically
