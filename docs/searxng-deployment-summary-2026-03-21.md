## Configuration Lessons Learned

### ❌ What Didn't Work

1. **Custom settings.yml with ConfigMap**
   - Schema validation errors: `ValueError: Invalid settings.yml`
   - Missing required fields or incorrect YAML structure
   - SearXNG extremely strict about settings schema

2. **[redis] section in limiter.toml**
   - Error: `data_dict 'redis': key unknown in schema_dict`
   - **Root cause:** Redis/Valkey configuration belongs in settings.yml, NOT limiter.toml

3. **VALKEY_URL environment variable**
   - Environment variable not recognized by SearXNG startup code
   - Configuration must be in settings.yml

### ✅ What Works

**Current Configuration:**
- **Settings:** Auto-generated by SearXNG (emptyDir mount)
- **Limiter:** Disabled (`limiter: false`)
- **Engines:** Google, StackOverflow, GitHub (enabled via SEARXNG_DISABLED_ENGINES env var)
- **Access:** NodePort 30080 on all cluster nodes

## Best Practices Discovered

### From Official SearXNG Repository

**1. limiter.toml Structure** (from `searxng/searxng`):
```toml
[botdetection]
ipv4_prefix = 32
ipv6_prefix = 48

trusted_proxies = [
  '127.0.0.0/8',
  '::1',
  '10.0.0.0/8',      # Kubernetes pod network
]

[botdetection.ip_limit]
filter_link_local = false
link_token = false

[botdetection.ip_lists]
block_ip = []
pass_ip = [
  '10.0.0.0/8',      # Allow internal cluster traffic
]
pass_searxng_org = true
```

**2. settings.yml Valkey Configuration** (from official docs):
```yaml
server:
  limiter: true

valkey:
  url: "valkey://localhost:6379/0"
```

**Key Insight:** Valkey/Redis is configured in **settings.yml**, not limiter.toml!

### Kubernetes Best Practices

**1. Network Isolation:**
- ✅ Separate namespace for search service
- ✅ Network policies restricting ingress/egress
- ✅ Co-locate SearXNG and Redis on same node (nexus)

**2. Resource Management:**
- ✅ Small memory footprint for Redis (64Mi)
- ✅ Reasonable limits for SearXNG (512Mi)
- ✅ CPU requests prevent overcommitment

**3. Service Exposure:**
- ✅ NodePort for external access (30080)
- ✅ ClusterIP for internal access (10.0.0.230:7777)
- ✅ Pod replicas: 1 (sufficient for internal use)
