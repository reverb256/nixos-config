## 🔍 Root Cause Analysis

### Direct Cause
Multiple pods stuck in `ContainerCreating` on Sentry node:
- `cloudflared-7f8c8fc8dc-48r7d` - Stuck for 5h46m
- `helper-pod-create-pvc-*` - Stuck for 3m+
- `helper-pod-delete-pvc-*` - Stuck for 30s+
- `operator-inventory-hardware-discovery-sentry` - Continuously restarting
- `searxng-*` - Stuck and retrying

### Why It Caused IP Exhaustion
1. **Ghost Allocations**: Each failed sandbox creation attempt reserved an IP in Flannel's database
2. **No Cleanup**: Failed pods didn't release the reserved IPs
3. **Continuous Retry**: Pods kept retrying, accumulating more ghost allocations
4. **Subnet Full**: 254 IP limit (10.244.2.1-10.244.2.254) reached

### Underlying Issue
```
no IP addresses available in range set: 10.244.2.1-10.244.2.254
```

The Sentry node's pod CIDR (10.244.2.0/24) only has 254 usable IPs. With ghost allocations, the subnet appeared full even though only ~15 actual pods were running.

2. **Watch Sandbox Failures**: Alert on FailedCreatePodSandBox events
3. **Namespace Pod Limits**: Already have LimitRange in place (enforced)

### Long-term Improvements
1. **Flannel IP Cleanup**: Implement periodic garbage collection of stale allocations
2. **Pod Creation Timeout**: Configure kubelet to give up on sandbox creation faster
3. **Larger Subnets**: Consider moving to /23 subnets (510 IPs) instead of /24 (254 IPs)
4. **Alternative CNI**: Calico supports larger IP pools and better garbage collection
