## VIP vs Local IPs

### OLD Configuration (Insecure)
```yaml
apiVersion: v1
clusters:
- cluster:
    insecure-skip-tls-verify: true  # ❌ Security risk
    server: https://10.1.1.110:6443  # Zephyr local IP (SPOF)
  name: kubernetes
```

### NEW Configuration (Secure + HA)
```yaml
apiVersion: v1
clusters:
- cluster:
    certificate-authority: /var/lib/kubernetes/secrets/ca.pem  # ✅ Secure TLS
    server: https://10.1.1.100:6443  # VIP (HA - auto-failover)
  name: local
```

---

## Benefits of VIP Configuration

1. **High Availability:** VIP automatically moves to healthy control plane node
   - Zephyr (10.1.1.110) - Priority 100 (primary)
   - Nexus (10.1.1.120) - Priority 100 (secondary)
   - Sentry (10.1.1.140) - Priority 90 (tertiary)

2. **Zero Downtime:** If Zephyr fails, VIP moves to Nexus/Sentry in <30 seconds
3. **No Reconfiguration:** Kubectl continues working without config changes
4. **Secure TLS:** Proper CA certificate verification (no insecure-skip-tls-verify)

## Manual Setup (If Needed)

**Update kubeconfig to use VIP:**
```bash
# Set server to VIP
kubectl config set-cluster local --server=https://10.1.1.100:6443

# Set CA certificate
kubectl config set-cluster local \
  --certificate-authority=/var/lib/kubernetes/secrets/ca.pem

# Test connection
kubectl get nodes
```

## Verification

**Test VIP connection:**
```bash
# Check current endpoint
kubectl config view --minify -o jsonpath='{.clusters[0].cluster.server}'

# Should output: https://10.1.1.100:6443

# Verify cluster access
kubectl get nodes
# Should show all 4 nodes: forge, nexus, sentry, zephyr
```

**Test HA failover:**
```bash
# Stop kube-apiserver on Zephyr
ssh zephyr "sudo systemctl stop kube-apiserver"

# VIP should move to Nexus or Sentry
# Check VIP ownership:
ssh zephyr "ip addr show eth0 | grep 10.1.1.100"

# Kubectl should still work (VIP auto-failover)
kubectl get nodes

# Restart Zephyr API server
ssh zephyr "sudo systemctl start kube-apiserver"
```

## Troubleshooting

**Issue:** "certificate signed by unknown authority"
**Solution:** 
```bash
kubectl config set-cluster local \
  --certificate-authority=/var/lib/kubernetes/secrets/ca.pem \
  --embed-certs=false
```

**Issue:** "connection refused"
**Solution:** Check if kube-apiserver is running:
```bash
ssh zephyr "sudo systemctl status kube-apiserver"
ssh zephyr "sudo systemctl restart kube-apiserver"
```

**Issue:** VIP not responding
**Solution:** Check Keepalived status:
```bash
ssh zephyr "sudo systemctl status keepalived"
# Check which node owns VIP:
ssh zephyr "ip addr show eth0 | grep 10.1.1.100"
```
