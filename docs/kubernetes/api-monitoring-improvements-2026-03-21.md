## 🔴 Critical Issues Discovered

### 1. **Prometheus RBAC Permissions** ✅ FIXED
**Problem**: Prometheus was using the `default` service account which lacked cluster-wide permissions.

**Impact**:
- Could not scrape pods, nodes, services, or endpoints
- Monitoring was incomplete for weeks
- No visibility into cluster resource usage

**Solution**:
- Created dedicated ServiceAccount `prometheus` in monitoring namespace
- Granted ClusterRole permissions for:
  - nodes, nodes/proxy
  - services, endpoints, pods
  - ingresses
  - nonResourceURLs: /metrics

**Verification**:
```bash
# Before: Many "forbidden" errors in Prometheus logs
# After: Clean logs, successful scraping of kubernetes-pods
```

---

### 2. **No API Server Alerting** ✅ FIXED
**Problem**: No alerts configured for API server availability, latency, or restarts.

**Impact**:
- API instability from 8,500 pod deletions went undetected
- No proactive monitoring of control plane health
- Manual intervention required to discover issues

**Solution**: Created 7 critical alert rules in `api-server-alerts.yml`:

| Alert | Trigger | Severity | Purpose |
|-------|---------|----------|---------|
| **APIServerDown** | API unavailable >1min | critical | Detect API server outages |
| **APIServerHighErrorRate** | 5%+ error rate | warning | Catch API degradation |
| **APIServerHighLatency** | p99 >1s | warning | Performance issues |
| **APIServerRestart** | Restart <5min ago | critical | Detect crashes |
| **APIServerPodCountMismatch** | ≠3 pods | critical | HA issues |
| **ControlPlaneHighRestartRate** | >5 restarts/hour | warning | Unstable pods |
| **EtcdHighRequestDuration** | p99 >500ms | warning | Backend issues |

**Files Created**:
- `/etc/nixos/kubernetes-manifests/monitoring/api-server-alerts.yaml`
- `/etc/nixos/kubernetes-manifests/monitoring/prometheus-rbac.yaml`
