## GPU Counting Issue

### Problem

**Sentry's AMD GPU is being incorrectly counted in the NVIDIA GPU total**

**Node GPU Inventory**:
- **forge**: 2× NVIDIA RTX 4060 + 2× AMD 5700XT = 4 GPUs total
  - Provider counts: **2 GPUs** ✅ (correctly ignores AMD)
- **nexus**: 1× NVIDIA RTX 3060 Ti = 1 GPU
  - Provider counts: **1 GPU** ✅
- **zephyr**: 2× NVIDIA RTX 3090 = 2 GPUs
  - Provider counts: **2 GPUs** ✅
- **sentry**: 1× AMD RX 5600XT = 1 GPU
  - Provider counts: **1 GPU** ❌ (should be 0)

**Expected**: 5 NVIDIA GPUs total (forge: 2, nexus: 1, zephyr: 2)
**Actual**: 6 GPUs total (5 NVIDIA + 1 AMD from sentry)

### Root Cause

The Akash provider has **inconsistent AMD GPU filtering**:

**Observed Behavior**:
- **forge** (2 NVIDIA + 2 AMD): Provider counts **2 GPUs** ✅ (ignores AMD correctly)
- **sentry** (1 AMD only): Provider counts **1 GPU** ❌ (counts AMD incorrectly)

The provider seems to use the logic: "Count all GPUs EXCEPT AMD GPUs on nodes that also have NVIDIA GPUs". This is inconsistent.

**Expected Behavior**: Provider should ONLY count `nvidia.com/gpu` resources, ignoring `amd.com/gpu` on ALL nodes.

### Evidence: Node Labels

```
forge:    nvidia.com/gpu.present = "true"  ✅
nexus:    nvidia.com/gpu.present = "true"  ✅
sentry:   nvidia.com/gpu.present = (empty) ❌ No NVIDIA GPU
zephyr:   nvidia.com/gpu.present = "true"  ✅
```

Sentry correctly does NOT have the `nvidia.com/gpu.present` label (because it has AMD GPU), but the provider is still counting its AMD GPU.

### Sentry GPU Details

**Kubernetes Node Resources**:
```
Allocatable:
  amd.com/gpu: 1  ← AMD RX 5600XT (should NOT be counted)
  cpu: 16
  memory: ~30GB
  ephemeral-storage: ~221GB
```

**Note**: Sentry has AMD GPU only (no NVIDIA GPU), so `nvidia.com/gpu.present` label is absent.

**Node Labels** (GPU-related):
```
akash.network/capabilities.storage.class.beta2: "1"
akash.network/capabilities.storage.class.beta3: "1"
akash.network/capabilities.storage.class.ram: "1"
```

**Missing**: No NVIDIA GPU labels (correct - sentry has AMD, not NVIDIA)

## Possible Solutions

### Option 1: Custom NVIDIA GPU Label (Recommended)

Add a custom label to explicitly mark nodes with countable NVIDIA GPUs:
```bash
kubectl label node forge akash.network/gpu.nvidia.count=2
kubectl label node nexus akash.network/gpu.nvidia.count=1
kubectl label node zephyr akash.network/gpu.nvidia.count=2
# Sentry does NOT get this label (has AMD, not NVIDIA)
```

Then configure provider to use this label for GPU counting instead of aggregating all GPU types.

**Pros**: Explicit, vendor-specific, prevents sentry AMD GPU from being counted
**Cons**: Requires provider configuration change or custom patch

### Option 2: Fix Provider to Use nvidia.com/gpu Resource

Configure or patch provider to ONLY count `nvidia.com/gpu` resources, ignoring `amd.com/gpu` entirely.

**Implementation**: Provider should filter nodes by `nvidia.com/gpu.present=true` label and sum only `nvidia.com/gpu` allocatable resources.

**Pros**: Correct fix, uses standard Kubernetes labels
**Cons**: Requires provider code/config change, may need upstream contribution

### Option 3: Exclude Sentry from GPU Inventory (Quick Fix)

Add sentry to operator-inventory exclusion list, but configure provider to still use sentry's CPU/memory/storage:

```yaml
exclude:
  nodes: []  # Don't exclude entire node
  gpu:  # Exclude sentry's GPU specifically
    nodes:
      - sentry
```

**Pros**: Quick workaround
**Cons**: Not clean, may not be supported by operator-inventory config schema

### Option 4: Report as Provider Bug (Long-term)

This is inconsistent behavior in Akash provider v0.10.7-events-static:
- Ignores AMD GPUs on nodes with NVIDIA GPUs (forge)
- Counts AMD GPUs on nodes with only AMD GPUs (sentry)

**Pros**: Proper upstream fix, helps other users
**Cons**: May take time to be resolved and released
